# 🤖 Gemini 인공지능 기반 서비스 전환 및 개발 개선 계획서 (AI Enhancement Plan)

> **문서 버전**: v1.0.0  
> **기반 API**: Google Gemini 2.5 Flash (`@google/genai`)  
> **작성일**: 2026-08-27  

---

## 1. 개요 및 배경

기존 '점심 메뉴 스무고개'는 클라이언트 룰베이스(Rule-based) 가중치 엔진으로 동작하도록 설계되어 있었습니다.  
실제 **Google Gemini API Key**가 확보됨에 따라, 규칙 기반의 한계를 넘어 **LLM 기반의 초개인화된 문맥 이해 및 실시간 지능형 대화 서비스**로 단계적 전환을 추진합니다.

---

## 2. 하이브리드 아키텍처 (Hybrid AI + Fallback)

네트워크 불안정, API 할당량 초과 또는 키 미설정 상황에서도 사용자는 **100% 무중단 서비스**를 경험할 수 있도록 하이브리드 안전망 구조로 설계되었습니다.

```text
[User Chat Answers] 
        │
        ▼
[Next.js Server API: /api/recommend-ai]
        │
   ┌────┴────────────────────────┐
   │ (정상 통신)                  │ (오류 / 키 부재 / 타임아웃)
   ▼                             ▼
[Gemini 2.5 Flash 추론]      [Local Rule-based Fallback Engine]
- 문맥 기반 1/2순위 선별         - 다차원 태그 가중치 알고리즘
- 위트 있는 맞춤형 사유 생성       - 지터(Jitter) 및 다양성 확보
   │                             │
   └──────────────┬──────────────┘
                  ▼
          [Result View] (1/2순위 추천 렌더링)
```

## 3. 단계별 AI 개발 개선 로드맵

### 🚀 Phase 1: LLM 실시간 지능형 추천 및 동적 사유 생성 (기반 구축 완료)
- **현황**: ✅ **구현 및 연동 완료**
- **내용**:
  - `@google/genai` 공식 SDK 연동 및 API Key 환경변수 안전 처리
  - `/api/recommend-ai` 엔드포인트 구축
  - 사용자의 7턴 답변을 종합 프롬프트로 구성하여 Gemini가 1순위/2순위 메뉴와 맞춤형 위트 추천 사유(`matchReason`)를 실시간 생성
  - API 실패 시 기존 룰베이스 엔진으로의 부드러운 자동 Fallback 보장

### 🔮 Phase 2: 다이내믹 AI 대화형 스무고개 (Dynamic Question Generation)
- **목표**: 고정된 7개 질문 대신, 이전 답변에 맞춰 AI가 실시간으로 질문을 생성하는 인터랙티브 대화
- **세부 과제**:
  - `POST /api/chat-ai`: 사용자 답변에 따라 마스코트 AI가 문맥에 맞는 다음 질문과 3~4개의 추천 선택지(Chips)를 실시간 생성
  - 예: "어제 과음했다"고 입력 시 ➔ "속이 많이 쓰리시겠어요! 해장용 국물이 필요하신가요?" 자동 질문 전개
  - Server-Sent Events (SSE) 기반 스트리밍 응답으로 타이핑 버블 연출 극대화

### 🔮 Phase 3: 비정상 입력 및 비속어에 대한 지능형 공감 대응
- **목표**: 정규식 기반 비속어 필터링을 넘어, 모호하거나 엉뚱한 입력("우주선 먹고 싶어", "아무거나")에 대해 마스코트 AI가 재치 있는 대화로 복구
- **세부 과제**:
  - Safety Setting 및 System Instruction 고도화
  - 마스코트 캐릭터 페르소나(친절하고 유쾌한 점심 요정) 프롬프트 튜닝

### 🔮 Phase 4: 영양 정보 및 위치 기반 확장 (Optional)
- **목표**: 추천된 메뉴의 대략적인 칼로리/영양 팁 및 날씨 API와의 결합
- **세부 과제**:
  - 현재 날씨(비, 눈, 폭염 등)에 맞춘 점심 메뉴 추천 가중치 자동 보정

## 4. 제미나이 모델 및 비용/성능 최적화 가이드

1. **권장 모델**: `gemini-2.5-flash`
   - 초고속 응답 속도(Latency < 800ms) 및 저렴한 토큰 비용
   - 점심 메뉴 추천 및 실시간 대화에 가장 이상적인 모델
2. **응답 포맷 제어**: `responseMimeType: "application/json"`
   - 프론트엔드 파싱 오류 원천 차단
3. **토큰 최적화**: 메뉴 풀과 시스템 프롬프트를 압축하여 요청당 300~500 토큰 이내로 관리
