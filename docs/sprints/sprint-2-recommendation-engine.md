# 🏃 Sprint 2: 텍스트 분석 & 추천 알고리즘 고도화 (Recommendation Engine)

## 1. 스프린트 개요
- **목표**: 사용자 자유 텍스트 및 선택값을 정밀 분석하여 적합한 1순위, 2순위 점심 메뉴를 도출하는 룰베이스 추천 엔진 구현
- **기간/우선순위**: P0 (핵심 비즈니스 로직)
- **상태**: ✅ **완료 (Completed)**
- **관련 PRD 항목**: `REQ-01`, `REQ-03`, `REQ-06`, `REQ-08`, `REQ-10`

---

## 2. 세부 개발 태스크 (Tasks)

### Task 2.1: 메뉴 데이터베이스 & 다차원 태그 체계 확장
- [x] 24종의 풍부한 점심 메뉴 데이터 세트 구축 (`lib/lunch-data.ts`)
- [x] 다차원 태그 정의:
  - 온도/국물: `soup`, `cold`, `warm`, `dry`
  - 맵기: `spicy`, `mild-spicy`, `nonspicy`
  - 요리 국적: `korean`, `japanese`, `chinese`, `western`, `asian`
  - 주식 형태: `rice`, `noodle`, `bread`, `salad`
  - 포만감/무게: `heavy`, `light`
  - 가격/상황: `cheap`, `premium`, `solo`, `share`, `quick`
- [x] 메뉴별 매력적인 한 줄 소개 문구(`blurb`) 및 이모지/힌트(`emojiHint`), 카테고리 보강

### Task 2.2: 자연어 키워드 매퍼 (`lib/keyword-mapper.ts`)
- [x] 사용자 직접 입력 텍스트에서 주요 음식 성향 키워드 추출:
  - 동행/상황: "혼자", "팀원들이랑", "회식", "간단히", "빠르게"
  - 선호/식성: "얼큰한", "담백한", "기름진", "고기", "다이어트", "비건"
  - 부정 표현: "느끼한 거 싫어", "국물 빼고", "밀가루 안 됨"
- [x] 부정 키워드에 대한 페널티(음수 가중치) 계산 로직

### Task 2.3: 가중치 스코어링 및 1순위/2순위 추천 산출
- [x] 누적된 사용자 답변 태그 + 키워드 태그 합산 스코어링 (`lib/recommend-engine.ts`)
- [x] 상위 1순위(Primary), 2순위(Alternative) 메뉴 선별 (다양성 확보)
- [x] 동점 처리 및 미세 무작위성(Jitter) 부여로 매번 동일한 결과 방지
- [x] 메뉴 카드별 맞춤형 추천 이유(위트 있는 매칭 사유) 동적 생성 (`generateMatchReason`)

### Task 2.4: 재추천(Followup) 엔진 연동
- [x] 이전 라운드에서 추천된 1/2순위 메뉴를 제외 목록(`excluded`)에 확실히 등록
- [x] 2개의 추가 질문(피하고 싶은 것, 현재 기분) 가중치 대폭 반영 (x2.5)
- [x] 추천 가능한 메뉴가 부족할 경우 Fallback 안전 메뉴 제공

## 3. 테스트 및 검증 기준 (Acceptance Criteria)
1. [x] 7문항 답변 후 항상 서로 다른 1순위, 2순위 메뉴 2개가 도출된다.
2. [x] 사용자가 "매운 국물 한식"을 집중 선택하면 김치찌개/순두부찌개 등이 상위에 추천된다.
3. [x] 직접 입력창에 "다이어트 가볍게"라고 입력하면 샐러드 등의 가벼운 메뉴에 가중치가 부여된다.
4. [x] 재추천 시 이전에 제시되었던 1/2순위 메뉴는 절대 다시 나타나지 않는다.
